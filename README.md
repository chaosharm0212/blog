# 知微 · 个人博客

一个可以双击打开的技术博客：界面简约，但阅读体验和交互细节都没省。

**没有构建步骤，没有依赖，没有 CDN。** 直接用浏览器打开 `index.html` 就能读。

```
blog/
├── index.html            ← 页面骨架 + 全部文章（Markdown 源文）
├── assets/
│   ├── css/style.css     ← 设计令牌、排版、组件、暗色主题
│   └── js/
│       ├── site.js       ← 站点配置：名字、简介、链接、年表
│       ├── markdown.js   ← Markdown 渲染 + 代码高亮（无依赖）
│       └── app.js        ← 路由、视图、搜索、目录、进度
└── README.md
```

---

## 1. 怎么看

直接双击 `index.html`。

想用本地服务器（地址更干净，部分浏览器行为更接近线上）：

```bash
python -m http.server 8080
# 然后访问 http://localhost:8080
```

> 之所以要保证「双击可读」，是因为它决定了整个技术方案：文章不能 `fetch`，
> 脚本不能用 ES Module，路由只能用 hash。这些在下面的取舍里都会解释。

## 2. 怎么加一篇文章

打开 `index.html`，找到文件末尾那段注释 `文章内容`，把下面的模板块复制一份，改掉内容即可：

```html
<script type="text/markdown">
---
title: 文章标题
slug: my-new-post
date: 2025-12-01
tags: [前端, 随笔]
featured: false
summary: 一句话摘要，会出现在列表页和搜索结果里。
---
正文就是普通 Markdown。

## 小标题

`行内代码`、**加粗**、[链接](https://example.com)、列表、表格、引用都支持。
</script>
```

要点：

- `slug` 决定地址（`#/post/my-new-post`），**不要重复**；
- `date` 用 `YYYY-MM-DD`，列表按它倒序，也会自动按年份分组；
- `featured: true` 只是给首页统计用，可以不加；
- 两个不能出现的字符串：`</script` 和 `<!--`——它们会提前结束 HTML 里的脚本块。
  写作时用「一个 script 标签」这样的描述代替，或在代码示例里省略。
- 加完文章后跑一次 `node tools/build-feed.mjs` 更新 RSS（不跑不影响网页本身，只是订阅源会缺新文章）。

## 3. 怎么改个人信息

**身份信息只在 `assets/js/site.js` 里写一次**，页头品牌字、页脚、版权年份、关于页、RSS 与
canonical 都从它读：

| 字段 | 作用 |
| --- | --- |
| `name` / `latin` | 站点名（页头、页脚、页面标题） |
| `url` | 站点地址，RSS 与 canonical 用它，结尾保留 `/` |
| `author` / `monogram` / `role` / `bio` | 署名、头像字、头衔、一句话简介 |
| `email` / `links` | 联系方式与社交链接（页脚与侧栏都渲染它） |
| `hero` / `lede` / `now` / `intro` / `timeline` / `stack` | 首页与关于页的文字 |

只有 `<head>` 里的 `<title>`、`description`、`og:*` 是静态写的（首帧前就要用，JS 来不及填），
换站名时顺手改一下即可。页脚现在会自动显示当年年份，不用每年手动改。

## 4. 功能清单

| 分类 | 细节 |
| --- | --- |
| 阅读 | 目录跟随滚动（窄屏自动变成折叠目录）、阅读进度条、正文宋体排版、表格/引用/代码样式、上一篇下一篇、预估阅读时长 |
| 代码 | 自研高亮（js / ts / css / html / sql / bash / py / go / rust / json）、一键复制、语言标签 |
| 发现 | `⌘K` / `Ctrl+K` 搜索面板（标题、摘要、正文、标签）、按标签筛选、归档页即时搜索 |
| 订阅 | RSS 2.0（含全文），由 `tools/build-feed.mjs` 从文章块生成；另有 `robots.txt` |
| 主题 | 浅色 / 深色，跟随系统偏好，记忆选择，首帧前应用（不闪白） |
| 体验 | 单页路由（无刷新）、入场动画、粘性页头、回到顶部、移动端抽屉菜单、打印样式 |
| 无障碍 | 跳转链接、焦点可见、`aria-current`、键盘可操作搜索、尊重 `prefers-reduced-motion` |

## 5. 设计上的几个决定

- **颜色**：米白纸面 + 墨色正文 + 一个陶土强调色（`#ad4a22`）。深色主题用暖灰而非纯黑。
- **字体**：标题宋体（`--font-display`），正文系统黑体（`--font-body`），代码等宽（`--font-mono`）。
  全部使用系统字体栈，不加载网络字体，因此没有字体阻塞。
- **层次**：靠 1px 发丝线和留白，而不是阴影和圆角卡片。
- **动效**：只做两件事——内容入场和链接下划线，时长 300–450ms，指数缓出。

改设计的话，优先动 `style.css` 开头的 `:root` 设计令牌，那里集中了颜色、字号、间距、
圆角与缓动函数；暗色主题的对应值在 `[data-theme="dark"]` 里。

## 6. 部署

整个目录就是产物，任何静态托管都能直接用。**四条路线的具体步骤见 [DEPLOY.md](DEPLOY.md)**
（局域网预览 / 临时公网隧道 / GitHub Pages / 国内云），这里只列最常用的：

- **GitHub Pages**：推到仓库，Settings → Pages 选分支根目录；
- **Vercel / Netlify**：导入仓库，构建命令留空，输出目录填 `blog`（或仓库根）；
- **对象存储**：把 `blog/` 整个上传，开启静态网站托管；
- **自己的服务器**：`rsync -a blog/ user@host:/var/www/blog/`。

因为路由用 hash、资源用相对路径，放在子目录（`https://user.github.io/blog/`）也能直接跑，
不需要配置 404 回退规则。

## 7. 已知取舍

- 没有评论：想讨论就写信，比评论区干净；
- **文章没有独立 URL**：地址是 `/#/post/slug`，而 `#` 后面的部分不会被搜索引擎单独收录，
  所以整站对 SEO 而言基本只有一个入口。这是「无服务器、无构建」换来的代价；真在意搜索流量时，
  要么改成真实路径（需要服务器回退配置），要么上 Astro 之类做静态多页；
- 没有站内图片优化：`<img>` 原样输出，图片请自己压到合理尺寸；
- 文章全部随首页加载（现在约 7000 字、130KB 资源）：文章上千篇时应该改成按需加载。

## 8. 想换成正式框架？

如果将来要上构建（Astro、Next、Eleventy），迁移成本很低：文章已经是标准 Markdown +
frontmatter，把它们从 `index.html` 的 `<script>` 块里复制出来，各自存成一个 `.md` 文件即可。
视图函数（`app.js` 里的 `viewHome` / `viewPost` / `viewPosts`）也可以直接改写成组件。
